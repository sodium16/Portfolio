# mcp-builder

**Self-Healing MCP-as-a-Service.** Paste a documentation URL → get a hosted, continuously-maintained MCP server that describes that API to AI coding agents (Claude, Cursor, etc.).

Built for the Bright Data hackathon. Full concept: [`idea.md`](./idea.md).

```
docs URL ──▶ Bright Data ──▶ LLM extract ──▶ structured spec ──▶ hosted MCP ──▶ Claude/Cursor
                │                                                    │
                └─── self-heal ──▶ diff ──▶ auto-publish / review ────┘
```

## What it does

1. **Crawls** a documentation site (e.g. `https://dummyjson.com/docs`) via the Bright Data Web Unlocker **REST API** (`POST https://api.brightdata.com/request`) — handles bot-blocking and CAPTCHAs. The zone is auto-detected from the account (`GET /zone/get_active_zones`), so no zone auto-creation (which requires a payment method) is needed.
2. **Extracts** a structured API representation with an LLM (OpenRouter): every endpoint becomes `{ name, description, method, path, parameters, response }`.
3. **Self-heals**: if a re-crawl drops a large fraction of known endpoints, the LLM diagnoses whether the docs genuinely changed or the extraction broke — and re-extracts with healing context.
4. **Diffs** the new spec against the published one.
   - **Non-breaking changes** (new endpoint, added optional param) → auto-published.
   - **Breaking changes** (removed param, type change, removed endpoint) → **held for review**, shown in the dashboard/review endpoint.
5. **Hosts** a versioned MCP server at `http://localhost:3000/mcp/<slug>` (Streamable HTTP transport).
6. **Re-syncs on a schedule** (default 10 min), using content hashes so an unchanged docs site costs only a cheap crawl — no LLM tokens wasted. If a source hits a provider rate limit (e.g. the free-model daily quota), it's cooled down for `SYNC_ERROR_COOLDOWN_MINUTES` (default 30) instead of being hammered on every tick.

## Quick start

```bash
pnpm install
cp .env.example .env        # fill in keys (see below)
pnpm -r build
pnpm dev                    # or: pnpm --filter @mcp-builder/api start
```

Open http://localhost:3000 — the dashboard lets you add a docs URL and watch its sync status.

### Create a source via the API

```bash
# create
curl -X POST http://localhost:3000/api/sources \
  -H "Content-Type: application/json" \
  -d '{"url":"https://dummyjson.com/docs","name":"DummyJSON API"}'

# trigger an immediate sync (scrape → extract → heal → publish)
curl -X POST http://localhost:3000/api/sources/<id>/sync -H "Content-Type: application/json" -d '{}'

# see the published manifest
curl http://localhost:3000/api/sources/<id>/manifest
```

### Connect the hosted MCP

Point Claude Desktop / Cursor at `http://localhost:3000/mcp/<slug>` as a **Streamable HTTP** MCP server. The server exposes one tool per documented endpoint. Tools are **documentation-reference** tools: they describe the API contract and parameters so an agent can build correct calls itself — they do not execute calls against production.

### Install as a local MCP server (Claude Code / Cursor / Codex)

You don't need our host at all. `GET /api/sources/<id>/install` returns everything to connect the source as a **project-scoped local stdio server** that these tools auto-detect:

```bash
curl http://localhost:3000/api/sources/<id>/install
# → { mcpJson, shimFile, shimCode, readme }
```

- **`.mcp.json`** (repo root) declares a `stdio` server — picked up automatically by Claude Code, Cursor, and Codex.
- **`.mcp/<slug>.mjs`** is a self-contained shim that **pulls the latest published spec** from our `/api/sources/<id>/spec` on every launch — so self-healing updates to the docs flow into your local agent without re-exporting.

The dashboard has an **"Install locally"** button that shows these files.

## Environment variables

See [`.env.example`](./.env.example) for all options.

| Var | Needed for |
| --- | --- |
| `OPENROUTER_API_KEY` | LLM extraction (`https://openrouter.ai/keys`) |
| `BRIGHT_DATA_API_KEY` | Production scraping via Web Unlocker REST API. *Optional:* without it, the scraper falls back to a plain HTTPS fetch so you can run the whole flow locally against public docs. |
| `BRIGHT_DATA_ZONE` | Web Unlocker zone name (optional — auto-detected via `/zone/get_active_zones` if empty) |

`OPENROUTER_MODEL` / `OPENROUTER_FALLBACK_MODELS` pick the model; the client cycles through fallbacks on rate limits and retries truncated output with a larger token budget. On a **free-tier key** (no prepaid credits, `usage`-only), the paid model variants 402 immediately and the `:free` models are capped by OpenRouter's `free-models-per-day` quota (429) — when that daily quota is exhausted, extraction fails until it resets. The fallback pool is pruned to models confirmed working on this key (`openai/gpt-oss-20b`, `openai/gpt-oss-20b:free`, `nvidia/nemotron-3-super-120b-a12b:free`, `cohere/north-mini-code:free`).

```
  api/            Express app: REST API, dashboard, hosted MCP routes, sync scheduler
packages/
  core/           Domain types, OpenRouter LLM client (model cycling), JSON store, hashing, env

  server/         buildMcpFromSpec() + Streamable HTTP MCP transport
```

## Self-healing in action

```text
Old spec:  create_user(name, email)
                     │
docs site redesigns / endpoint renamed
                     ▼
Re-crawl → extraction loses 3 of 6 endpoints
                     ▼
Heal check: dropped ratio ≥ 30% → LLM diagnoses
                     ▼
Re-extract with context: "previous spec had create_user, get_user, ..."
                     ▼
Diff: name → username  ⇒  BREAKING
                     ▼
Spec held for review (status: review) — publish manually
```

Non-breaking drift (e.g. a new `list_users` endpoint) flows straight to the hosted MCP without human involvement.

## What's verified working

- **Bright Data Web Unlocker via REST** (replaces the `@brightdata/sdk` auto-zone path): `https://dummyjson.com/docs` crawls **8 real pages, 0 errors** (previously the SDK 403'd on zone auto-creation and returned 0 pages / an empty fingerprint).
- Full pipeline (crawl → extract → heal → diff → build MCP) passes deterministically with a mock LLM: 6/6 checks. Published specs on **DummyJSON** (17 endpoints) and **JSONPlaceholder** (40 endpoints) are still served.
- **Self-healing demo, end to end**: local test docs (v1) → 10 endpoints published as spec v6 → docs flipped to v2 (breaking: `create_product` renamed `name`→`title`, dropped `category`/`inStock`) → re-sync → change **held for review** (`status: review`, `pending.healed: true`) while the hosted MCP keeps serving the stable v1 tools. Live trace:
  ```text
  [sync] src_25462e03 → ok (changed) — Published spec v6: + Added: list_products, get_product, …
  POST /sync → { breaking: true, "held for review. ! create_product: - name; - category; - inStock; + title (required)" }
  ```
- LLM resilience: model cycling (primary → fallbacks → `FREE_FALLBACKS`), truncation retry with a larger token budget, and a **schema-shape repair pass** that feeds a model its own malformed JSON + the zod error to fix it in place instead of re-extracting. Every LLM call has a hard timeout (120 s main, 60 s repair) so a slow model can't hang the pipeline.
- **Private/localhost URLs bypass Web Unlocker** — Bright Data's remote proxy can't reach local/intranet hosts, so `isPrivateUrl()` routes them through plain fetch; public URLs use the REST Web Unlocker.
- Hosted MCP handshake: discovery, `initialize` session, `tools/list`, `tools/call`, **multiple concurrent sessions** (no transport-collision crash).
- **Local stdio shim**: generated install files boot as a working MCP server (initialize → tools/list → tools/call over stdio), pulling the live spec.
- Timeout-bounded crawling and a local HTML→text fallback when no Bright Data key is set.

> **Note on the current key:** it's a **free-tier OpenRouter account** (`is_free_tier: true`, no prepaid credits). The paid model variants 402 instantly, and the `:free` models are capped by OpenRouter's `free-models-per-day` quota (429).
